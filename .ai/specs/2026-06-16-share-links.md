# Share Links

**Date:** 2026-06-16
**Status:** draft
**Area:** backend + frontend

---

## TLDR

Trainers can generate token-based, read-only share links for a client's training plan and/or workout results. Recipients open the link in a browser without logging in. Links have a mandatory expiry date and can be manually revoked.

---

## Problem Statement

There is no way to share a client's training plan or workout history with someone who does not have an account. Trainers need to give coaches, physios, or the client's family a read-only window into the data without creating accounts or sharing credentials.

---

## Proposed Solution

A new `share-links` Payload collection stores a UUID token linked to a plan. A public Next.js page at `/share/[token]` validates the token (active + not expired) and renders the requested data without authentication, using the existing dark-theme frontend layout with all interactive elements removed.

---

## Resolved Questions

- **Q1** — Full custom `ui` field component inside Payload Admin: shows the complete URL with a copy button. Uses `NEXT_PUBLIC_SERVER_URL` to compose the link.
- **Q2** — Same `[locale]/(frontend)` dark-theme layout is reused. Interactive elements (set-logging forms, logout button) are hidden.
- **Q3** — Results view shows full set-log detail per session: weight, reps, RIR, note per set, grouped by exercise.

## Data Model — `share-links` collection

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `label` | text | no | Human-readable name for trainer reference |
| `plan` | relationship → `plans` | yes | The plan being shared; sidebar |
| `token` | text, unique, indexed | — | UUID auto-generated by `beforeChange` hook on `create`; read-only in admin; sidebar |
| `shareUrl` | ui (custom component) | — | Renders full URL composed from `NEXT_PUBLIC_SERVER_URL + /share/ + token`; copy button; sidebar |
| `permissions` | select + hasMany | yes | Options: `plan` (Plan preview), `results` (Results / logs); default `['plan']`; sidebar |
| `expiresAt` | date + time | yes | Link is invalid after this timestamp; sidebar |
| `active` | checkbox | yes | Default `true`; set to `false` to revoke without deleting; sidebar |

**Access:** all CRUD operations `isAdmin` only. Clients cannot see or create share links.

**Token generation:** `beforeChange` hook calls `crypto.randomUUID()` when `operation === 'create'` and `data.token` is not set.

---

## Token Validation (loader)

`loadShareLink(token: string)` in `src/modules/sharing/server/load-share-link.ts`:

1. Query `share-links` with `where: { token: { equals: token } }`, `overrideAccess: true`, `limit: 1`
2. If no document found → return `null`
3. If `active !== true` → return `null`
4. If `expiresAt` is in the past (compare to `Date.now()`) → return `null`
5. Based on `permissions`:
   - `'plan'` present → load full plan hierarchy (microcycles → workouts → groups → exercise rows) for the linked plan, using `overrideAccess: true`; returns `TPlanAccordionItem[]`
   - `'results'` present → load workout-logs for workouts in the plan, then set-logs for those sessions, grouped by session then exercise; returns `TShareResults`
6. Return `{ meta: { planTitle, expiresAt, permissions }, plan?, results? }`

Public page returns `notFound()` when loader returns `null`.

## Public Page — `/share/[token]`

**Route:** `src/app/[locale]/(frontend)/share/[token]/page.tsx`
Inherits `[locale]/(frontend)/layout.tsx` (dark theme, CSS, NextIntlClientProvider).

**Header:** plan title + "Shared plan · expires [date]" — no greeting, no logout button.

**Plan section** (when `permissions` includes `plan`):
- Same accordion structure as the client dashboard (`WorkoutPlansAccordion`)
- All set-logging controls, series forms, and interactive buttons are hidden
- Prop `readOnly={true}` passed down — existing components adapted if needed, or a stripped variant created

**Results section** (when `permissions` includes `results`):
- Sessions list ordered newest-first
- Per session: workout name, date, duration (startedAt → finishedAt), notes
- Per session → exercises grouped by `exerciseName`
- Per exercise → set rows: set number, weight (kg) / bodyweight flag, reps, RIR, note

## Phasing

### Phase 1 — Data layer
Create `share-links` collection, export, register in config, run migration, regenerate types.
**Deliverable:** collection visible in Payload Admin, records can be saved with auto-generated token.

### Phase 2 — Admin UI component
Build `ShareLinkUrl` custom `ui` field component that reads the `token` field value and renders the full URL with a copy button.
**Deliverable:** share URL visible and copyable directly in the admin sidebar when viewing a share link record.

### Phase 3 — Public page
Build the loader, the share page, and any read-only variants of existing workout components.
**Deliverable:** opening `/share/[token]` in a browser shows the correct plan/results without login; expired or inactive links return 404.

## Risks & Impact

| Risk | Severity | Mitigation |
|------|----------|------------|
| Token guessing | low | UUID v4 has 2¹²² entropy — brute-force infeasible |
| Stale data on shared page | low | Server component — always fetches fresh data on each request |
| `overrideAccess: true` exposes other plans if loader has a bug | high | Loader always filters by the specific `planId` from the share-link doc; never accepts planId from the request |
| Existing workout components tightly coupled to interactive state | medium | Audit `WorkoutPlansAccordion` and `WorkoutTracker` for interactive dependencies before Phase 3 |
